# База знаний: долг и продуктовые ставки

Составлено 25 июля 2026 по итогам аудита всех 50 страниц объединённой базы знаний
(Long Story Short, Anima, Vortex, раздел для разработчиков).

Файл лежит в `docs/plans/`, но на сайт не попадает: каталог исключён из коллекции
контента в `src/content.config.ts`. Плановые документы можно называть как угодно,
публичной страницей они не станут.

Ничего из перечисленного не сделано — это бэклог. Задачи по переезду (правило service
worker, вырезание доки из Gatsby, nginx, раннер) живут отдельно, в
[`deploy/README.md`](../../deploy/README.md).

## Часть 1. Долг и качество

### 1.1 Требует решения владельца

**Опубликован URL Discord-вебхука.**
`docs/vortex/discord.mdx:26` и `docs/character-sheet/discord.mdx:32` показывают, как
выглядит URL вебхука, на примере реального токена. Проверено 25.07.2026: URL отдаёт
404, то есть вебхук мёртв и активной утечки нет. Но вебхук-URL — это по сути пароль на
запись в канал, публиковать его в таком виде нельзя.

- Заменить на заведомо поддельный: `https://discord.com/api/webhooks/1234567890/XXXXXXXX`.
- Отдельно проверить скриншот `docs/vortex/discord/assets/3.jpg` (подпись «Скопируйте
  URL вебхука») — токен может быть виден на картинке.

**У Anima нет ни одного скриншота.**
18 страниц, 0 изображений — при том что раздел описывает визуальный редактор.
Для сравнения: у Long Story Short 51 изображение. В тексте уже расставлены
**13 комментариев-заглушек** с описанием нужного кадра, например:

```
<!-- скриншот: виджет «Модификатор» со значением +3 и подписью «Сила» -->
```

Полный список — `grep -rn "скриншот:" docs/anima/`. Упирается в съёмку, её делает владелец.

**Страница-заглушка в публикации.**
`docs/anima/widgets/container.md` содержит «> В разработке», но стоит в сайдбаре наравне
с готовыми виджетами. Варианты: дописать, скрыть через `sidebar.hidden`, повесить бейдж
«Черновик».

**Пять запланированных страниц исчезли при переезде.**
В навигации Gatsby (`storyview/src/doc-content.ts`) они были помечены `isDisabled` и не
рендерились, при миграции не восстанавливались:

| Страница | Раздел |
|---|---|
| Переименование полей | Текстовый редактор |
| Теги | Организация персонажей |
| Доступ по ссылке | Организация персонажей |
| Работа с .json | Организация персонажей |
| Проблемы и их решение | Прочее |

Вместе с ними пропал целиком раздел **«Организация персонажей»** — все три его пункта
были отключены. Решить: вернуть в бэклог или закрыть намеренно.

**Возможная ошибка в данных.**
`docs/main/limits.mdx`: у ролей «Местный герой» и «Герой королевства» одинаковые лимиты —
300 персонажей и 400 заклинаний. Уточнить, так ли задумано.

### 1.2 Дублирование и поддержка

**Таблица переменных продублирована дословно.**
Одни и те же 10 строк (`[STR]`, `[DEX]`, `[PROF]`, `[LVL]` и т. д.) лежат в
`docs/character-sheet/expression-input.mdx` и `docs/text-editor/dice-roller.mdx`.
Лечится тем же приёмом, что уже применён к FAQ: вынести в `src/data/`, рендерить
компонентом из одного источника.

**Двойная навигация.**
Страницы Anima заканчиваются ручными строками «Смотрите далее», а Starlight под ними
рисует собственные «назад / вперёд» по порядку сайдбара. У Long Story Short ручных
ссылок нет вообще — то есть ещё и непоследовательно. Предложение: убрать ручные,
оставить встроенные.

**Устаревающие разделы стоят слишком высоко.**
«Отправлять броски в Telegram» и «в Discord» помечены как устаревшие и скоро отключаемые,
но занимают 3–4 позиции в «Основных возможностях» — выше живого Vortex. Опустить вниз
либо свернуть в одну страницу-указатель на Vortex.

### 1.3 Быстрые правки

| Что | Где | Объём |
|---|---|---|
| Опечатка «вкоре» → «вскоре» | `character-sheet/telegram.mdx:7`, `character-sheet/discord.mdx:7` | 2 замены |
| Пустые `alt` — 23 картинки из 51 | `vortex/*` (12), `character-sheet/telegram, discord, expression-input` (11) | по описанию из контекста |
| `className="table-container"` — наследие Gatsby, класса больше не существует | `main/limits.mdx:12` | 1 строка |
| Сырой HTML вместо markdown: 1 `<table>`, 13 `<a href>` | `main/limits.mdx`, `misc/license.mdx`, `user-guides/*` | механическая правка |

Пустые `alt` — это не только доступность, но и вес в поиске по картинкам при 51 скриншоте.

### 1.4 Инструменты

**Чекер ссылок не покрывает внешние адреса.**
`scripts/check-links.mjs` валидирует только `/doc/*`. Проверено вручную 25.07.2026: все
6 ссылок в приложение (`/spells/`, `/profile/`, `/gygax/`, `/characters/list/`,
`/characters/builder/`, `/long/character-creation/`) и 43 внешние ссылки живы. Но ссылки
в приложение ломаются именно при рефакторинге роутов, о котором документация не узнает.
Добавить проверку в CI, внешние — в мягком режиме, чтобы сборка не падала из-за чужого
таймаута.

**У longstoryshort.app нет `robots.txt`** — отдаёт 404. После переезда будет два сайтмапа:
`/sitemap-index.xml` от Gatsby и `/doc/sitemap-index.xml` от Starlight. Второй поисковики
сами не найдут. Добавить `robots.txt` в `static/` приложения со ссылками на оба.

## Часть 2. Продуктовые ставки

### 2.1 Живая песочница для нотации бросков — приоритет №1

Справочник по нотации описывает `{1d20, 1d20}kh1`, `4d6!`, `1d20cs=20cf=1` — знание,
которое читать бесполезно, а попробовать понятно мгновенно.

Технически проверено: движок `lss-dice` опубликован в публичном npm (версия 5.5.0, та же
линейка, что `@dice-roller/rpg-dice-roller` 5.5.1, который стоит в Anima). То есть
поведение песочницы будет совпадать с приложением побитово, а не «примерно».

Объём: остров Astro с полем ввода и кнопкой «Бросить», плюс кнопка «Попробовать» рядом
с каждым примером в `docs/anima/notation.md` — их там около сорока.

**Важное ограничение:** честно только для Anima. У листа D&D 5e движок другой и слабее
(`[STR]`, без приоритета операций) — там нужна либо своя песочница, либо никакой.

Почему первым: уникально для ниши, реализуемость подтверждена, ни от кого не зависит.

### 2.2 Демо-лист прямо в документации

У проекта есть SDK, встраивающий лист в чужую страницу через iframe. Документация — тоже
чужая страница. Живой лист, который можно потыкать без регистрации, даёт сразу три вещи:
онбординг лучше скриншота, демонстрацию продукта и доказательство работоспособности SDK
на его же странице.

**Блокер:** нужен публичный демо-персонаж или анонимный режим листа. Сейчас лист требует
авторизации. Без этого идея не летит — вопрос к владельцу.

### 2.3 Рецепты как каталог по системам

Сейчас `docs/anima/recipes.md` — одна страница с четырьмя примерами. Это самый ценный
формат из имеющихся: человек с готовой системой ищет «как собрать лист для Mothership»,
а не «что такое виджет Модификатор».

Разложить по системам (D&D 5e, Mothership, Forbidden Lands, Heart — они уже упоминаются
в разделе про композицию), у каждого рецепта копируемые формулы и ссылка на готовый
шаблон. Даёт вход для авторов шаблонов и попадание в запросы вида
«лист персонажа &lt;система&gt;», по которым проекта сейчас нет.

### 2.4 Витрина шаблонов сообщества

Авторы публикуют шаблоны Anima в Stable, их видят все. Страница со списком реальных
опубликованных шаблонов по системам замыкает круг: прочитал рецепт → посмотрел готовый
шаблон → сделал свой. **Зависимость:** нужен публичный список шаблонов из API, наличие
не проверено.

### 2.5 Фильтр поиска по продуктам

Pagefind поддерживает фасеты. Сейчас поиск глобальный: запрос «формулы» вернёт вперемешку
Anima и лист D&D — а это два разных движка с несовместимым синтаксисом. Фильтр по топику
снимает ровно ту путаницу, о которой предупреждает заметка на лендинге Anima.
Потребует доработки индексации Starlight.

### 2.6 Страница «Что нового»

Изменения по трём продуктам в одном месте. Даёт вернувшимся повод зайти, а команде —
место для анонсов, которые сейчас живут только в Telegram и там же тонут.

### 2.7 Глоссарий с всплывающими подсказками

В `docs/anima/faq.md` уже есть словарь терминов — «Алиас», «Дайсница», «Композиция».
По остальным страницам термины разбросаны без объяснений. Подсказка по наведению —
дешёвый компонент, заметно снижающий порог для новичка.

### 2.8 Кнопка «чего-то не хватает»

В репозитории уже есть шаблон issue (`.github/ISSUE_TEMPLATE/widget-request.yml`).
Ссылка внизу страницы, открывающая issue с подставленным названием страницы, превращает
читателя в источник бэклога. Порядка пяти строк работы.

### 2.9 Английская версия — только Anima и раздел для разработчиков

Лист D&D 5e с русскими переводами — продукт для русскоязычной аудитории. Anima
система-агностична, а SDK по определению рассчитан на внешних разработчиков, у которых
русский не обязателен. Starlight умеет i18n из коробки. Решать как продуктовую задачу
выхода на новую аудиторию, а не как задачу перевода документации.

## Часть 3. Измерение — сделать до выкладки

**Документация выпадет из аналитики.** У приложения site-wide стоит Яндекс.Метрика
(id 72398422, `gatsby-plugin-yandex-metrika`), которая сейчас считает в том числе
`/doc/*`. У сайта на Starlight аналитики нет вообще — после переезда по документации
наступит слепота. Это регрессия переезда, закрыть до выкладки.

При добавлении трекинга сразу логировать **поисковые запросы с нулём результатов**.
Это не метрика ради метрики: получается готовый отранжированный список того, что людям
нужно, а в документации не написано. Стоимость — один обработчик.
